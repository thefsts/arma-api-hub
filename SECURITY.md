# Security Policy

## Reporting a vulnerability

Do not disclose suspected vulnerabilities in public issues, discussions, pull requests, or social media.

Use GitHub private vulnerability reporting for this repository. Include:

- affected component and version or commit;
- clear reproduction steps;
- expected and observed behavior;
- impact and data classifications involved;
- logs or proof of concept with secrets and personal data removed;
- suggested mitigation, if known.

## Research boundaries

Authorization is limited to this repository's source code and explicitly designated test environments. It does not authorize testing of production systems, customer tenants, third-party services, FSTS products, physical security systems, or connected infrastructure.

Do not:

- access, retain, alter, or disclose another party's data;
- perform denial-of-service, social-engineering, persistence, or destructive testing;
- test credentials obtained from leaks or third parties;
- bypass rate limits or safety controls;
- expose an unremediated vulnerability publicly.

FSTS will validate reports, assess severity, coordinate remediation, and communicate disclosure timing. This policy does not promise a bounty or safe harbor beyond applicable written authorization.
